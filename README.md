# منصة الغيطي — Next.js + Express + MySQL

إعادة بناء لمنصة Django الأصلية كتطبيق JavaScript كامل: واجهة Next.js عربية RTL، واجهة API مستقلة بـ Express، وقاعدة بيانات علائقية MySQL. التطبيق القديم موجود في `../mudarris-platform/pro` كمرجع للمزايا والبيانات؛ لم يتم تعديل ملفات المصدر.

## التشغيل

1. ثبّت Node.js 20 أو أحدث وMySQL 8 أو أحدث.
2. للتشغيل المحلي السريع استخدم `run.bat`؛ سيجهّز مجلد MySQL محليًا خاصًا بالمشروع، يطبق الهجرات، ثم يشغّل الواجهة والـAPI.
3. للتشغيل اليدوي انسخ `.env.example` إلى `.env` واضبط اتصال MySQL ومفتاح JWT، ثم نفّذ `npm install` و`npm run db:migrate`.
4. شغّل المشروع بـ `npm run dev`؛ الواجهة على `http://localhost:3000` والـAPI على `http://localhost:4000/api`. الواجهة تستمع على الجهاز المحلي فقط افتراضيًا؛ عيّن `WEB_HOST` صراحةً إذا كان النشر يحتاج عنوان استماع مختلفًا.

قبل النشر شغّل `npm run check:production` لمراجعة المتغيرات الأساسية. خذ نسخة MySQL دورية عبر `npm run db:backup`، ويمكن تحديد `MYSQLDUMP_PATH` و`BACKUP_DIR` إذا لم تكن أداة `mysqldump` في PATH.

إعدادات PM2 وNginx وتعليمات النشر موجودة في `docs/DEPLOYMENT.md` و`deploy/`.

يُنشأ أول حساب مدرس عبر `npm --workspace apps/api run create:teacher -- --username teacher --password ... --name ...`.
لا توجد كلمات مرور افتراضية ولا أسرار مضمّنة في الشيفرة.

## تقسيم النظام

- `apps/web`: صفحات Next.js ومكوّنات React وملفات التنسيق.
- `apps/api`: Express، المصادقة، صلاحيات الطالب والمدرس، وخدمات المجال.
- `apps/api/db/migrations`: مخطط MySQL المناظر لنماذج المنصة.
- `apps/api/src/scripts/import-django-sqlite.ts`: استيراد اختياري لقاعدة Django SQLite إلى MySQL عبر الأمر `npm --workspace apps/api run import:django`؛ راجع تعليمات الترحيل أدناه.

## المزايا المنقولة

الحسابات والأدوار، الصفوف، الكورسات والمحاضرات والدروس والمرفقات، الاشتراكات وأكواد التفعيل، التقدم، الامتحانات وأسئلتها ودرجاتها، الإعلانات والآراء ورسائل التواصل، الأجهزة وسجلات التقارير الأسرية. الـAPI يقدم مسارات عامة وحسابات ولوحة الطالب ولوحة المدرس، بما يشمل إدارة المحتوى والطلاب والأكواد والرسائل والاشتراكات والنتائج.

## نقل بيانات SQLite القديمة

1. أوقف الكتابة على المنصة القديمة وخذ نسخة احتياطية من `db.sqlite3` و`media/`.
2. اضبط بيانات MySQL في `.env` وشغّل هجرات المخطط.
3. نفّذ `npm --workspace apps/api run import:django -- --sqlite "مسار\db.sqlite3"`.
4. راجع تقرير الاستيراد، ثم انقل مجلدات `media` القديمة إلى `apps/api/uploads` يدويًا بعد التحقق من الملفات.

أداة النقل لا تمسح المصدر ولا تتجاوز الجداول غير المعروفة. جرّب النقل على نسخة من قاعدة البيانات قبل نقل بيانات الطلاب الفعلية.

بعض بيانات Django الحالية أنشأها الأمر `seed_demo.py` لأغراض العرض، بما فيها روابط فيديو لا تخص دروس اللغة العربية. راجع الفيديوهات والشهادات والكورسات التجريبية قبل إتاحة المنصة للطلاب.

## تكاملات وميزات تحتاج إعدادًا عند النشر

رفع الملفات والفيديو إلى تخزين إنتاجي يحتاج volume دائمًا أو طبقة Object Storage أمام `UPLOAD_ROOT` مع نسخ احتياطية؛ النسخة المحلية تحفظ الملفات في مجلد API. إرسال تيليجرام والبريد ورسائل واتساب يحتاج إعداد الاعتمادات وخدمات الإرسال. حماية الفيديو في المتصفح ليست وسيلة لمنع تسجيل الشاشة؛ تبقى صلاحيات الوصول وروابط البث الموقعة في الخادم.

الفيديوهات المرفوعة تُشفّر على القرص بمفتاح `VIDEO_ENCRYPTION_KEY`، ويفك الخادم تشفير الأجزاء المطلوبة فقط بعد التحقق من جلسة المشاهدة. أنشئ المفتاح مرة واحدة واحفظه مع النسخ الاحتياطية بسرية؛ فقدانه يجعل الفيديوهات غير قابلة للتشغيل. بعد استيراد ملفات قديمة نفّذ `npm --workspace apps/api run encrypt:videos` مرة واحدة. لا تغيّر المفتاح بعد التشفير دون إعادة تشفير الملفات. التشفير يحمي الملف المخزن؛ المتصفح يستقبل أجزاء مفكوكة التشفير للتشغيل، لذلك لا يمنع تصوير الشاشة أو نسخ البث بواسطة مستخدم مصرح له بشكل مطلق.
